# Read · TXT 专项（P2.1）

更新时间：2026-11-15

## 定位

TXT 与 EPUB、PDF 同属长期核心阅读格式。优先实现真实可阅读、分页准确、阅读进度可复原的基础，不开发社交、主题商店、会员广告。本文件针对 PR #3 的源码变更；**PR 未通过 CI / 真机验证前，不能宣称已交付稳定 APK**。

## 本轮提交的代码

| 功能 | 实现 | 验收要求 |
|---|---|---|
| 连续超长段落分页 | `paginateSlices` 用 TextPainter 测量并按页拆分，不要求文本含换行 | 数千字符无换行文本，分页后逐页拼接必须与原内容一致 |
| 不漂移的分页偏移 | `PageSlice(start,end)` 不依赖 `indexOf(pageText)`，阅读页以章节字符偏移恢复 | 重复行、空行、换字号、旋转屏幕后不得丢/重复一段内容 |
| Unicode | UTF-16 代理项成对保留，不能拆分表情字符 | 中文、emoji、混合文本做单测及真机验证 |
| 文本解码 | 既有 UTF-8（含 BOM）、GB18030 路径；新增 UTF-16 LE/BE BOM | Windows 导出的文本与中文电子书不得乱码 |
| 章节识别 | 标题正则不跨行吞换行，长于 100 字符的假标题不拆章 | 目录与正文映射，拼接所有章节完全等于原文本 |
| 导入安全 | 文件超 40MB 在加载前直接提示，原文件保留 | 不崩溃、不占用过量内存，提示下一阶段大文件分块加载 |

## 尚未解决（必须做，不能假完成）

1. **真正超大 TXT：** 当前 `LibraryStore` 仍为整本字节加载并保留 `Book.content`。40 MB 限制只是防止直接 OOM 的暂行策略，不是分块阅读。下一阶段要先改持久化为 drift/SQLite 索引，按字节偏移、编码及章节建立索引，按需只取可见章节，避免一次性载入。
2. **GB18030 Windows/Android 真机验收：** 有格式转换降级路径，但仍需带实际样书的测试证据。不能因为代码存在就标“百分百兼容”。
3. **章节规则可编辑：** 尚未实现自定义正则、手工编辑目录或全文内容替换。
4. **同步：** 字符偏移进入当前本地进度存储；**尚未**连接 WebDAV、加密、冲突合并或 Windows 客户端。
5. **进度保护：** 读书应用必须在崩溃、升级、导入同名书与断电时保留原文件和进度，待 SQLite 事务/备份实现并真机检验。
6. **多种格式：** EPUB 当前仍是文字解析；PDF/MOBI/AZW3/CHM/DOCX/CBZ/CBR 未实现，独立排期。
